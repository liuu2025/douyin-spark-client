# 本地预览说明

本文档说明如何在本机查看 `douyin-spark-client` 前端效果，以及如何选择后端启动方式。

后端启动和客户端接入的长期备忘见 `docs/后端启动与客户端接入备忘.md`。接口细节以最新 HTTP 接口文档为准。本文档只记录前端开发最常用的启动方式。

## 快速命令速查

以下命令都是完整可用命令，简短版和详细版效果一致。如果你已经熟悉流程，看简短版就够了；第一次使用建议看详细版，了解每一步的作用。

### 只看页面和普通接口（后端用 go run）

| 步骤 | 简短命令 | 详细命令（效果完全一致） |
|------|----------|------------------------|
| 进入后端目录 | `cd ..\douyin-spark` | `cd D:\Projects\test\douyin-spark-workspace\douyin-spark` |
| 启动后端 | `go run ./cmd/server` | `go run ./cmd/server -addr 127.0.0.1:8787 -enable-poller=false` |
| 停止后端 | `Ctrl+C` | 在运行 go run 的窗口按 `Ctrl+C` |
| 进入前端目录 | `cd ..\douyin-spark-client` | `cd D:\Projects\test\douyin-spark-workspace\douyin-spark-client` |
| 安装依赖 | `npm.cmd install` | `npm.cmd install`（如已安装可跳过） |
| 启动前端 | `npm.cmd run dev` | `npm.cmd run dev -- --port 5173` |
| 停止前端 | `Ctrl+C` | 在运行 npm 的窗口按 `Ctrl+C` |
| 健康检查 | `Invoke-RestMethod http://127.0.0.1:8787/health` | `Invoke-RestMethod -Method Get -Uri http://127.0.0.1:8787/health` |
| 打开页面 | 浏览器打开 `http://127.0.0.1:5173/` | 同左 |

说明：

- `go run ./cmd/server` 默认使用 `-addr 127.0.0.1:8787`、`-enable-poller=true`、`-poller-interval 10s`。本地开发通常关掉轮询避免自动发送，所以详细版加了 `-enable-poller=false`。
- `npm.cmd run dev` 默认端口也是 5173，所以简短版不需要显式指定 `--port`。
- 简短版命令中用相对路径 `..\douyin-spark`，前提是你当前在 `douyin-spark-client` 目录。如果不在，请用绝对路径或先 cd 到对应目录。

### 测试智能客服（Go 后端 + assistant + 前端）

智能客服页面需要三段服务同时运行：

```text
前端 Vite
  -> Go 后端 /api/v1/assistant/...
  -> douyin-spark-assistant
```

| 步骤 | 命令 |
|------|------|
| 启动 assistant | `cd D:\Projects\test\douyin-spark-workspace\douyin-spark-assistant` 后执行 `D:\Apps\DevTools\Miniconda3\envs\langchain1.2\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000` |
| 启动 Go 后端 | `cd D:\Projects\test\douyin-spark-workspace\douyin-spark` 后执行 `go run ./cmd/server -addr 127.0.0.1:8787 -enable-poller=false -assistant-url http://127.0.0.1:8000` |
| 启动前端 | `cd D:\Projects\test\douyin-spark-workspace\douyin-spark-client` 后执行 `npm.cmd run dev -- --port 5173` |
| assistant 健康检查 | `Invoke-RestMethod http://127.0.0.1:8000/health` |

- 前端不要直接请求 `http://127.0.0.1:8000`。

- 如果 8000 端口提示已占用，说明本机已有 assistant 进程在运行，需要先关闭旧进程或换端口并同步修改 `-assistant-url`。

## 结论

只看前端页面和普通接口：

```text
后端用 go run 启动
前端用 npm.cmd run dev 启动
浏览器打开 http://127.0.0.1:5173/
```

要完整测试"添加/重新登录抖音号"的远程浏览器登录：

```text
后端用 Docker Compose 启动
前端仍然用 npm.cmd run dev 启动
浏览器打开 http://127.0.0.1:5173/
```

原因是远程浏览器登录依赖 Chromium、Xvfb、x11vnc、websockify 和 noVNC，这些依赖已经打包在后端 Docker 环境里。直接用 Windows 本地 `go run` 时，通常缺少 Xvfb/noVNC 这套 Linux 图形和远程控制组件，容易出现本地能调接口、但远程控制窗口起不来的情况。

要测试“智能客服”：

```text
assistant 用 Python/uvicorn 启动
Go 后端用 -assistant-url 指向 assistant
前端用 npm.cmd run dev 启动
浏览器打开 http://127.0.0.1:5173/assistant
```

### 什么时候选哪种

| 场景 | 推荐后端 | 说明 |
|------|----------|------|
| 只改前端代码 | go run | 不需要重建 Docker |
| 只测普通页面和接口 | go run | 登录、注册、列表、详情、发送任务配置等 |
| 测试添加/重新登录抖音号 | Docker | 需要 noVNC 远程浏览器 |
| 测试智能客服 | go run + assistant | 需要 Go 后端代理和 Python assistant 同时运行 |
| 改了后端代码且前端要用 Docker 联调 | Docker（带 `--build`） | 需要重新构建镜像 |

## 方式一：普通页面和普通接口联调（go run）

适合开发这些页面：

- 登录和注册。
- 仪表盘。
- 抖音号列表。
- 抖音号详情（登录状态读取、发送任务配置等）。
- 管理员权限拦截页面。
- 管理员登录态导入表单页面。

不适合完整测试远程浏览器登录（添加/重新登录抖音号）。

### 1. 启动后端

进入后端项目目录：

```powershell
cd D:\Projects\test\douyin-spark-workspace\douyin-spark
```

简短命令（最常用）：

```powershell
go run ./cmd/server
```

详细命令（显式指定全部参数，效果同上）：

```powershell
go run ./cmd/server -addr 127.0.0.1:8787 -enable-poller=false
```

`-enable-poller=false` 会关闭后台自动发送轮询器，避免本地开发时调度已有的发送任务自动运行。后端默认 `-enable-poller=true -poller-interval 10s`，如果本地需要测试轮询行为，可以不加 `-enable-poller=false`。

> **停止方式：** 在运行 `go run` 的 PowerShell 窗口按 `Ctrl+C`。
>
> **修改代码后：** 需要先 `Ctrl+C` 停止当前进程，再重新执行启动命令，新代码才会生效。

检查后端是否启动成功：

```powershell
Invoke-RestMethod -Method Get -Uri http://127.0.0.1:8787/health
```

成功时应返回：

```json
{
  "status": "ok"
}
```

### 2. 启动前端

进入前端项目目录：

```powershell
cd D:\Projects\test\douyin-spark-workspace\douyin-spark-client
```

首次运行先安装依赖：

```powershell
npm.cmd install
```

简短命令：

```powershell
npm.cmd run dev
```

详细命令（显式指定端口）：

```powershell
npm.cmd run dev -- --port 5173
```

PowerShell 里请使用 `npm.cmd`，不要直接使用 `npm`。部分 Windows 环境会因为脚本执行策略阻止 `npm.ps1`。

> **停止方式：** 在运行 `npm.cmd run dev` 的 PowerShell 窗口按 `Ctrl+C`。

### 3. 打开页面

浏览器打开：

```text
http://127.0.0.1:5173/
```

前端会通过 Vite 代理访问后端：

```text
前端页面地址： http://127.0.0.1:5173/
后端接口地址： http://127.0.0.1:8787/api/v1
代理配置见 vite.config.ts
```

## 方式二：完整远程浏览器登录联调（Docker）

适合测试这些流程：

- 添加抖音号（完整远程浏览器登录流程）。
- 重新登录已有抖音号。
- 创建登录会话 -> 打开 `remote_url` -> 用户远程操作 -> `login_confirming` 确认 -> 最终绑定。
- 管理权转移场景（另一个客户端账号成功登录已归属的抖音号）。

### 1. 启动 Docker Desktop

先打开 Docker Desktop，等待 Docker Engine 完全启动。

### 2. 启动后端 Docker

进入后端项目目录：

```powershell
cd D:\Projects\test\douyin-spark-workspace\douyin-spark
```

简短命令（代码没变的情况下可用，跳过构建）：

```powershell
docker compose -f docker-compose.example.yml up -d
```

详细命令（第一次启动或代码变更后必须用这个，会重新构建镜像）：

```powershell
docker compose -f docker-compose.example.yml up -d --build
```

> **区分 `--build` 和 `restart`：** 当前 Dockerfile 会把后端 Go 代码复制进镜像并编译。如果修改了后端 Go 代码，必须用带 `--build` 的命令，新代码才会生效。下面这个命令不会包含刚修改的 Go 代码：
>
> ```powershell
> docker compose -f docker-compose.example.yml restart    # 不会重新构建！
> ```
>
> **修改后端代码后联调的完整步骤：**
> 1. `Ctrl+C` 停止前端（或保持运行，不需要停）。
> 2. `docker compose -f docker-compose.example.yml up -d --build` 重建并重启后端。
> 3. 如果前端还在运行，直接刷新浏览器页面；如果已停，重新 `npm.cmd run dev`。

检查后端：

```powershell
Invoke-RestMethod -Method Get -Uri http://127.0.0.1:8787/health
```

成功时应返回：

```json
{
  "status": "ok"
}
```

查看容器状态：

```powershell
docker compose -f docker-compose.example.yml ps
```

查看后端日志：

```powershell
# 只看最近日志
docker logs douyin-spark

# 实时跟踪日志（按 Ctrl+C 退出）
docker logs -f douyin-spark
```

停止后端容器（数据不会丢失，见下方数据目录说明）：

```powershell
docker compose -f docker-compose.example.yml down
```

### 3. 启动前端

前端仍然在 `douyin-spark-client` 目录启动：

```powershell
cd D:\Projects\test\douyin-spark-workspace\douyin-spark-client
npm.cmd run dev -- --port 5173
```

### 4. 打开控制台并完成添加抖音号

浏览器打开：

```text
http://127.0.0.1:5173/
```

登录后进入抖音号列表，点击"添加抖音号"。

前端会调用：

```text
POST /api/v1/login-sessions
```

如果后端远程浏览器启动成功，响应里会有 `remote_url`。前端会自动新开标签页打开远程浏览器。

常见远程浏览器地址类似：

```text
http://127.0.0.1:6081/vnc.html?autoconnect=true&resize=scale
```

用户需要在这个远程浏览器里完成：

- 打开抖音登录页，扫码。
- 处理可能出现的滑块或人机验证。
- 输入短信验证码。
- 登录成功后处理"保存登录信息"弹窗。

服务端会后台监测浏览器是否已登录成功。检测到登录成功后，登录会话进入 `login_confirming` 阶段（默认 90 秒确认期）。

控制台页面会轮询登录会话状态。进入 `login_confirming` 后，确认远程窗口没有未处理的弹窗（如二次滑块/风控），再点击：

```text
我已确认，完成登录
```

前端调用：

```text
POST /api/v1/login-sessions/{session_id}/confirm
```

服务端进入 `finalizing` 阶段，重新保存 `storageState.json`、识别 `douyin_id`、写数据库并关闭远程浏览器。最终状态进入 `logged_in` 后，前端会刷新抖音号列表。

如果用户不手动确认，服务端会在 90 秒后自动收尾。

### 5. 取消登录

如果登录会话进行中想退出，在控制台抽屉里点击：

```text
取消登录
```

前端会调用：

```text
POST /api/v1/login-sessions/{session_id}/cancel
```

服务端会关闭远程浏览器和 noVNC 资源，并把会话标记为 `cancelled`。


```text
登录页 -> 普通用户注册
```

注册流程：先请求发送 QQ 邮箱验证码，再提交验证码和密码完成注册。如果后端没有启用 QQ 邮箱 SMTP 配置，开发模式下验证码通常会打印在后端控制台日志里。

## 数据目录

后端数据默认保存在：

```text
D:\Projects\test\douyin-spark-workspace\douyin-spark-data\
```

包含：

- `app.sqlite`：SQLite 数据库，保存客户端账号、抖音号归属、登录会话、发送任务和运行记录。
- `login_sessions/`：临时登录会话数据。
- `douyin_accounts/<douyin_id>/state/storageState.json`：抖音号登录态文件（Playwright browser state）。
- `douyin_accounts/<douyin_id>/runtime/`：运行日志和诊断截图。

`storageState.json` 是浏览器登录凭证，不要提交到 GitHub 或分享给无关人员。

> **数据不会随重建丢失：** `docker compose down` 只是停止容器，不会删除宿主机上的 `douyin-spark-data` 目录。重新构建镜像或重建容器后，之前的 SQLite 数据库、登录态和运行日志仍然保留。如果需要清空测试数据，在停止后端后手动处理 `douyin-spark-data` 目录。

## 常见问题

### 1. 前端页面能打开，但登录接口失败

确认后端是否在 `127.0.0.1:8787` 启动：

```powershell
Invoke-RestMethod -Method Get -Uri http://127.0.0.1:8787/health
```

### 2. PowerShell 不能运行 npm

使用：

```powershell
npm.cmd run dev
```

不要使用：

```powershell
npm run dev
```

### 3. 添加抖音号没有远程窗口

如果后端是 `go run` 启动，通常只能测普通接口，不适合完整远程浏览器登录。因为 Windows 本地缺少 Xvfb、x11vnc、websockify 和 noVNC。

请改用 Docker 后端：

```powershell
docker compose -f docker-compose.example.yml up -d --build
```

### 4. remote_url 打不开

确认：

- Docker 后端已启动。
- `http://127.0.0.1:8787/health` 正常。
- noVNC 端口 `6081` 没有被占用。
- 返回的 `remote_url` 是当前浏览器可访问的地址。

### 5. 登录会话状态长时间不变

- 确认远程浏览器页面已打开并且可以操作。
- 确认用户已经在远程浏览器中完成扫码和登录。
- 查看后端 Docker 日志：`docker logs -f douyin-spark`。
- 如果服务端已检测到登录成功但状态卡在 `login_confirming`，可以手动点击"我已确认"来提前结束确认期，否则等待 90 秒自动收尾。

### 6. 验证码没有发到 QQ 邮箱

后端开发模式下，如果未启用 QQ 邮箱 SMTP 配置（未挂载 `qq-mail.yaml`），验证码会降级为打印到服务端控制台。请在控制台日志中查找验证码。

真实部署时需要配置 `qq-mail.yaml` 并作为只读文件挂载到 Docker 容器。后续部署参数以最新后端 HTTP/部署说明为准。

### 7. Docker Desktop 启动或构建失败

- 确认 Docker Desktop 已完全启动（桌面图标不再闪动）。
- 首次构建可能较慢，需要下载 Playwright 依赖和 Chromium。
- 如果报 `please install the driver` 错误，说明镜像缺少 Playwright driver 文件，确认 `Dockerfile` 已正确复制 `/ms-playwright-go/` 目录。

### 8. 改了后端代码但 Docker 容器里没生效

`docker compose restart` 不会重新构建镜像。必须用：

```powershell
docker compose -f docker-compose.example.yml up -d --build
```

当前 Dockerfile 会把后端代码复制进镜像并编译，只有 `--build` 才会触发重新复制和编译。
