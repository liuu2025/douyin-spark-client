# 后端启动与客户端接入备忘

本文档是 `douyin-spark-client` 前端项目的长期备忘，用来沉淀后端启动方式和客户端接入流程。

后续如果 `docs-后端生成的说明文档/后端启动说明.md` 和 `docs-后端生成的说明文档/客户端接入说明.md` 被删除，前端开发仍可参考本文档。新的接口细节仍以最新的 `docs-后端生成的说明文档/HTTP接口文档.md` 或用户后续提供的 HTTP 接口文档为准。

## 后端启动方式

普通接口联调用 Go 进程即可：

```powershell
cd D:\Projects\test\douyin-spark-workspace\douyin-spark
go run ./cmd/server -addr 127.0.0.1:8787 -enable-poller=false
```

适合测试：

```text
账号注册/登录
当前用户信息
通知公告
客服聊天
抖音号列表和详情
发送任务创建/编辑/暂停/恢复
管理员权限拦截
不需要远程浏览器的接口
```

完整远程浏览器登录流程用 Docker：

```powershell
cd D:\Projects\test\douyin-spark-workspace\douyin-spark
docker compose -f docker-compose.example.yml up -d --build
```

远程登录依赖 Chromium、Xvfb、x11vnc、websockify、noVNC，这些依赖在 Docker 镜像内。测试“添加抖音号 / 重新登录抖音号”时优先用 Docker。

健康检查：

```powershell
Invoke-RestMethod -Method Get -Uri http://127.0.0.1:8787/health
```

后端接口基址：

```text
http://127.0.0.1:8787/api/v1
```

前端开发服务器：

```powershell
cd D:\Projects\test\douyin-spark-workspace\douyin-spark-client
npm.cmd run dev -- --port 5173
```

浏览器打开：

```text
http://127.0.0.1:5173/login
```

Vite 已把 `/api/v1` 代理到 `http://127.0.0.1:8787`。

## 智能客服联调

智能客服需要同时启动三个服务：

```text
浏览器前端
  -> Go 后端 /api/v1/assistant/...
  -> douyin-spark-assistant
```

assistant 启动示例：

```powershell
cd D:\Projects\test\douyin-spark-workspace\douyin-spark-assistant
D:\Apps\DevTools\Miniconda3\envs\langchain1.2\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Go 后端启动时指定 assistant 地址：

```powershell
cd D:\Projects\test\douyin-spark-workspace\douyin-spark
go run ./cmd/server -addr 127.0.0.1:8787 -enable-poller=false -assistant-url http://127.0.0.1:8000
```

前端仍然只请求 `/api/v1/assistant/...`，不要直连 `http://127.0.0.1:8000`。Go 后端会校验当前用户 token，并把 token 转发给 assistant。

常用接口：

```text
POST   /api/v1/assistant/chat
POST   /api/v1/assistant/chat/stream
GET    /api/v1/assistant/conversations
POST   /api/v1/assistant/conversations
GET    /api/v1/assistant/conversations/{conversation_id}
DELETE /api/v1/assistant/conversations/{conversation_id}
```

## 客户端账号模型

客户端账号和抖音号是两个概念：

```text
客户端账号 user：登录控制台的人。
抖音号 douyin_account：被该客户端账号管理的抖音业务资产。
```

一个客户端账号可以管理多个抖音号。

当前用户常见字段：

```text
id
public_uid
qq_email
role
status
```

当前后端没有正式昵称字段。前端如果展示昵称，只能临时存在浏览器本地，直到后端新增数据库字段和接口。

QQ 邮箱验证码由服务端生成、发送、哈希保存和校验。前端只负责让用户输入邮箱、验证码和密码。

密码规则：

```text
长度 6-20 个字符
至少包含 1 个数字
至少包含 1 个非数字字符
只允许大小写字母、数字、英文点号 .、下划线 _、短横线 -
不允许空格、中文或其他符号
```

## 抖音号管理模型

抖音号唯一业务 ID 是登录成功后从抖音网页识别出的 `douyin_id`。

前端展示和传参时只使用业务 ID：

```text
douyin_id
task_id
target_public_uid
```

前端不要传、不要展示、不要依赖这些服务端内部路径：

```text
storage_state_path
runtime_dir
account_dir
storageState.json 路径
```

登录态文件由服务端根据数据库归属关系决定使用。管理员导入登录态文件时是例外，接口是：

```text
POST /api/v1/admin/storage-state-imports
```

## 新增或重新登录抖音号

当前主流程是远程浏览器人工登录，不是前端二维码展示，也不是前端短信验证码输入。

流程：

```text
1. 前端调用 POST /api/v1/login-sessions
2. 后端创建 login_session，并启动远程 Chromium/noVNC
3. 后端返回 session_id、remote_url、remote_status、expires_at
4. 前端新开标签页打开 remote_url
5. 用户在远程浏览器里完成扫码、滑块、风控、短信验证码和保存登录信息
6. 前端轮询 GET /api/v1/login-sessions/{session_id}
7. 状态为 waiting_manual_login 时，提示用户继续在远程窗口登录
8. 状态为 login_confirming 时，提示用户确认远程窗口没有未处理弹窗
9. 用户可点击确认，前端调用 POST /api/v1/login-sessions/{session_id}/confirm
10. 状态为 finalizing 时，提示正在保存登录状态
11. 状态为 logged_in 时，刷新抖音号列表或进入抖音号详情页
```

用户取消时调用：

```text
POST /api/v1/login-sessions/{session_id}/cancel
```

取消用于释放远程浏览器资源，并避免创建或转移抖音号管理权。

以下接口属于旧自动登录兼容流程，前端主流程不要使用：

```text
GET  /api/v1/login-sessions/{session_id}/qr-image
POST /api/v1/login-sessions/{session_id}/sms-code
POST /api/v1/login-sessions/{session_id}/resend-sms
```

## 管理权规则

一个抖音号同一时间只有一个当前管理者。

推荐理解：

```text
最后一次成功完成远程浏览器登录的客户端账号，获得该抖音号当前管理权。
```

登录成功后：

```text
douyin_id 不存在：
  创建 douyin_account，owner_user_id 为当前客户端账号。

douyin_id 已存在且属于当前客户端账号：
  刷新 storageState，login_state 更新为 ok。

douyin_id 已存在但属于其他客户端账号：
  管理权转移给当前客户端账号。
  旧归属进入 transferred / disabled，不再参与自动发送。
```

前端应把管理权转移看成业务状态，不要尝试直接操作服务端目录。

## 登录状态和验证

客户端推荐把底层登录态包装成“抖音登录状态”。

读取最近一次结果：

```text
GET /api/v1/douyin-accounts/{douyin_id}/login-status
```

立即启动浏览器验证：

```text
POST /api/v1/douyin-accounts/{douyin_id}/login-status
```

常见登录状态文案：

```text
not_checked             未验证
ok                      有效
not_logged_in           已失效
missing_storage_state   登录文件缺失
identity_mismatch       账号不匹配
check_failed            验证失败
transferred             已转移
```

`storageState.json` 不能靠文件存在判断有效。有效性只能由服务端启动浏览器、访问抖音、抓取当前 `douyin_id` 并和数据库记录比对。

检测到失效时，不建议删除登录态文件。前端应提示用户验证或重新登录，并暂停自动发送。

## 自动发送和任务

前端只负责配置和开启/暂停，后端轮询器负责按周期执行。

抖音号自动发送开关：

```text
PATCH /api/v1/douyin-accounts/{douyin_id}/polling
{
  "enabled": false
}
```

内部状态：

```text
enabled=true  -> douyin_accounts.status = active
enabled=false -> douyin_accounts.status = paused
```

前端文案：

```text
active -> 已开启
paused -> 已暂停
disabled -> 已禁用
```

开启自动发送前，服务端应校验：

```text
owner 匹配
douyin_accounts.status = active
douyin_accounts.login_state = ok
send_tasks.status = active
```

如果抖音登录状态不可用，服务端返回 `login_state_not_ok`，前端提示：

```text
抖音登录状态已失效，请先验证登录状态或重新登录后再开启自动发送。
```

发送任务运行记录是追加式记录。前端展示“最近一次自动发送”时优先读取运行流水状态：

```text
running   本周期正在运行
sent      本周期已发送
skipped   本周期跳过
failed    本周期失败
```

## 状态速查

登录会话状态：

```text
created                   已创建登录会话
remote_browser_starting   正在启动远程浏览器
waiting_manual_login      等待用户在远程浏览器中完成登录
login_confirming          已检测到登录成功，等待用户确认或确认超时
finalizing                正在保存最终登录态并绑定抖音号
logged_in                 登录成功
failed                    登录失败
cancelled                 用户取消
timeout                   登录会话超时
```

运行状态：

```text
idle       空闲
sending    正在发送
running    运行中
sent       已发送
skipped    已跳过
failed     失败
paused     暂停
disabled   禁用
```

## 前端第一版不做

第一版前端不要做这些事：

```text
不要展示二维码图片作为新增抖音号主流程
不要提供抖音短信验证码输入框作为主流程
不要解析 storageState.json 判断身份
不要传服务端文件路径
不要让用户直接编辑 Playwright 选择器
不要把 acct_xxxxxx 暴露成产品概念
不要在登录前创建最终抖音号资产
不要登录状态失败一次就要求删除登录态文件
```
